## 1. Goals and expected behaviour

**Goal.** On a phone (640 px and below) the header is one row: the logo and a Menu (burger) button. The button, or a click on the header row, opens a drawer from the right. The drawer holds "All events", then the nav link, name and role, and Log out (or Log in, Sign up and the role switch). It is modal: a backdrop covers the page, the page behind is inert, focus stays inside, the page does not scroll. It closes with its Close button, the backdrop, Escape or a navigation. On a wider screen the header is the one-row layout of today plus the visible link "All events" (D73): no button, no drawer, no backdrop. No new features beyond the drawer, "All events" and the Close button.

**Behaviours.** Each line is checked with a component test in `web/src/auth/Header.test.tsx` (`fetch` mocked), or by hand when it needs layout, CSS or animation (jsdom has no layout and does not read `styles.css`; see "How the tests see open and closed"). "Test first" ones get the test before the code.

**How the tests see open and closed.** jsdom does not read `styles.css`, so `display: none`, `visibility: hidden` and `transform` are invisible to it and every item of a closed drawer still counts as present and reachable. Therefore tests read state from `aria-expanded` on the button, `data-open` on the drawer, and `role="dialog"`, `inert`, `body.style.overflow` for the modal state, never from visibility. This keeps every existing header and screen test green without opening the menu first. The CSS facts (closed drawer gone from the screen, Tab and accessibility tree, HR20; desktop showing everything, HR19; animation, HR36; layering, HR37) are checked by hand. HR26 and HR35 fake "button not displayed" with an inline `style.display = "none"` on the button, which `getComputedStyle` in jsdom honours.

**Why the drawer stays in the DOM (not mounted/unmounted, not `hidden`).** The brief asked for always-in-DOM with `visibility: hidden`. It is also the better option here: unmounting would cut the slide-out animation and change the DOM seen by about 30 existing tests; the `hidden` attribute would hide it from `getByRole` in jsdom (tests would need to open the menu first) and needs a desktop override. `visibility: hidden` with a delayed transition keeps the exit animation, removes closed items from Tab and the accessibility tree, and the state is visible to jsdom through `data-open`. No better jsdom-testable option found.

**Out of scope.** A sticky or fixed header; a drawer or backdrop on desktop; swipe gestures; a drawer from the left; a second drawer level; a focus-trap or dialog library; new links, texts or icons beyond the burger icon (`Menu`), the X icon (`Close menu`) and "All events" (shown on desktop too, D73; no other desktop link is added); a user menu with the name as a button; avatar; notifications; changing the logo, `/` or `/organizer`; the text of "My events" / "My registrations"; translations; dark theme; changing other screens or the 520 px rules of other components (the event card).

**Assumptions.** Change any of these first in this file.
- **Phone option (D66, D69): a Menu button and a modal right drawer (D70).** Chosen over A (always-visible rows, D65) and C (free wrap). Cost accepted by the user: Log out and the nav link take two taps, and there is open/close, focus and scroll-lock state to test.
- **Burger breakpoint: 640 px, for the header only** (`@media (max-width: 640px)`). The single-row desktop header does not fit between 521 and about 640 px (P9). 640 px is already the table scroll limit in `brand.md`. At 641 px and above the desktop layout applies. The old `@media (max-width: 520px)` block keeps only the event-card rules; its header rules move to the 640 px block and are reworked for the drawer (HR18). The width at which one row stops fitting on desktop for a very long name is handled by the ellipsis (HR8).
- **The header row click only opens (D67 reworked for D69).** A toggle by the header row cannot work with a modal drawer: the backdrop covers the header while open. Opening is idempotent, which also removes the double-toggle risk (HR24).
- **"All events" in the drawer (D68) and on desktop (D73)**: shown at every width, no media query hides it. The logo still links to `/` too (D64). It is rendered by `NavMenu`, so it is absent while `me` is pending (logo only), on desktop too; kept on purpose, no extra code (recommendation, D73). jsdom sees it in the DOM whenever `NavMenu` renders (HR27).
- **`inert` and not `aria-hidden` (HR33)**, set with `setAttribute` on `main`, the logo and the Menu button, because the drawer lives inside the `header` and cannot be hidden itself. No library.
- **`role="dialog"` and `aria-modal` only while open (HR29)**, so desktop never exposes a dialog.
- **No `hidden` attribute, no unmounting** (see "Why the drawer stays in the DOM").
- Colours: no new colour. The backdrop is `--text` at 40% opacity (a tint of an existing colour); the drawer is `--surface` with a `--border` line.
- The button label is `aria-label="Menu"` on an icon-only button (inline SVG, `aria-hidden`, no library); the Close button is `aria-label="Close menu"`.
- The menu state is reset on a change of logged in / logged out (key), and closed on a new location key (HR16). It is not stored anywhere else and not kept across reloads.
- Row order inside the drawer is the DOM order; no CSS `order`.
- The name is not a link and not a button. The divider is decorative (CSS border) and has no role. The header is not sticky. The text is English only.

## 3. Architecture decisions

- **Apps:** `web/` only. `Header.tsx` and `styles.css`. No new dependency, no library for the menu, the trap or the dialog.
- **State:** one `useState<boolean>` for open in `NavMenu` (stays in `Header.tsx`; split a file only if it grows over about 150 lines). `Header` keeps `<NavMenu key={me.data ? "in" : "out"}>` and renders nothing for the menu while `me.isPending`. The `key` resets the state on login and logout (HR17).
- **Markup:** `NavMenu` returns the Menu button (`type="button"`, `aria-label="Menu"`, `aria-expanded`, `aria-controls={panelId}`, no `onClick`), then `div.nav-backdrop` (`aria-hidden`, `onClick` = close with focus return, HR32), then the drawer `div.site-header-end` (`id`, `data-open`, `aria-label="Menu"`, `data-role`, and `role="dialog"` + `aria-modal="true"` only when open, `onKeyDown` for the trap). The drawer children are: the Close button, `<nav aria-label="Site">` with the "All events" `Link` (`aria-current` from `pathname === "/"`), then the existing `Account` / logged-out `nav`.
- **Handlers on `header`:** `onKeyDown` Escape (as built, now with focus return after `inert` is gone) and a new `onClick` (HR21): returns if `open`, if the target is inside `a`, `.site-header-end` or `.nav-backdrop`, or if `getComputedStyle(menuButton).display === "none"` (HR26); otherwise sets open to `true`. Both reach `NavMenu` through the existing `useImperativeHandle` handle (add `open(event)`), as the Escape handler does.
- **Effects in `NavMenu`:** (a) location `key` sets false, no focus move (HR16); (b) while open: set `inert` on `main`, logo and Menu, set `body.style.overflow = "hidden"`, focus the Close button; the cleanup removes `inert`, restores the old overflow value (HR33, HR34); (c) `resize` listener on `window` while open: close if the Menu button is not displayed (HR35). Focus return to Menu (Escape, Close, backdrop) must run after the cleanup of (b), so `inert` is gone when `focus()` is called: do it in an effect that reacts to a "return focus" ref flag set by those three closers, not directly in the event handler. The logo and Menu elements are reached through `ref`s passed to `NavMenu` (or `document.querySelector` inside the `header`); `main` through `document.querySelector("main")`.
- **Trap:** `onKeyDown` on the drawer: on `Tab` (and Shift+Tab) at the last (first) of `querySelectorAll("a[href], button:not(:disabled)")` call `preventDefault` and focus the other end (HR31).
- **CSS:** `.nav-toggle`, `.nav-close`, `.nav-backdrop` (all `display: none` by default); `.site-nav-all` has NO `display: none` rule and no phone-only `display: flex` rule (D73): it is a normal `.site-nav` at every width (the rules `.nav-backdrop, .site-nav-all { display: none }` and the `.site-nav-all { display: flex }` in the 640 px block are removed; keep `.nav-backdrop` hidden by default); one block `@media (max-width: 640px)` with: those three shown, header padding, the fixed drawer with `transform`/`visibility`/transition and the `[data-open="true"]` rule, the backdrop with `opacity`/`visibility`/transition and its open rule, stacked nav links, horizontal divider, account row with Log out on the right; one `@media (prefers-reduced-motion: reduce)` setting transitions to `none`. Remove the header rules from the old 520 px block. Reuse the 44 px and focus-ring rules; no new colours (backdrop `--text` at 40%, e.g. `color-mix` or an `rgba` of the same hex, whichever the file already uses).
- **Accessibility:** real `<button>`s with state in `aria-expanded`; the drawer is a dialog only while open; the page is `inert` behind it; closed items are out of Tab and the accessibility tree by `visibility: hidden` (HR20). Landmarks keep their labels; `Site` is a new third label, only one landmark of each name.
- **No library, no `matchMedia`, no `hidden`, no `tabindex` on the header or the backdrop.**
- **Layout and CSS are not testable in jsdom:** HR18 to HR20, HR36, HR37, HR8, HR10 are by hand; HR1 to HR6, HR11 to HR17 and HR21 to HR35 are DOM tests.
